# Кодекс: найти, прочитать и править прозу автора

Ситуация: автор просит посмотреть, что у него записано про Шир, дописать страницу, завести
новую или связать её с объектом мира.

**Кодекс — не часть модели мира.** Это место, где автор думает: справочник, наброски, разбор
персонажей. Страница про Мордор не делает Мордор объектом мира, а объект «Мордор» может
существовать вовсе без страницы. Поэтому правится кодекс файловыми инструментами, а не
тулами.

## Тулы текста не отдают, и это не пробел

Проза правится файлами. Тулы нужны ровно для одного: **по файлам страницу не найти по
идентификатору**. Ссылка `codex_page:<guid>` лежит в `objects/` и `events/`, а сам
идентификатор спрятан во frontmatter страницы — файловым поиском его придётся вылавливать по
всему дереву.

```
get_world_object {objectId}                → codexPage: "codex_page:<guid>"
find_codex_pages {query: "codex_page:…"}   → путь к файлу от корня рабочей папки
<файловые инструменты>                     → читать и править по этому пути
```

Идентификаторов сразу несколько — `resolve_codex_paths` переведёт их пачкой за один вызов.
Идентификатора нет вовсе, есть только название — тот же `find_codex_pages` с названием в
`query`; он ищет по названию, пути и идентификатору.

## Устройство страницы

Одна страница — один markdown-файл. Иерархия выражена папками: у страницы с детьми рядом
лежит папка с тем же именем без расширения.

```
codex/
  Шир.md
  Шир/
    Хоббитон.md
    Хоббитон/
      Бэг-Энд.md
  Мордор.md
```

**Заголовок страницы — имя файла** без расширения; родитель — папка, в которой файл лежит. В
самом файле ни того, ни другого нет, и дублировать их заголовком первой строки не нужно.

Переименовать страницу значит переименовать файл **и её папку**; перенести — переместить файл
вместе с папкой. Забыть про папку — значит осиротить всех детей.

```
---
id: codex_page:3f9a2b1c-...      # менять нельзя
tags: [город, интриги]           # опционально
summary: |-                      # опционально
  Две-три фразы о том, что на странице.
---
Текст страницы целиком.
```

`summary` — изложение страницы **для модели**: то, что уходит в контекст вместо всего текста.
Прозой, но без художественности. Пишешь длинную страницу — напиши и `summary`, иначе она будет
попадать в контекст целиком или не попадать вовсе.

Заводя новую страницу, `id` не выдумывай: приложение проставит его само. Менять `id`
существующей нельзя — на неё ссылаются объекты и события.

## Ссылки в прозе

На сущность ссылаются обычной markdown-ссылкой, где адресом стоит идентификатор:

```markdown
Кольцо досталось [Фродо](world_object:d0000000-0000-4000-8000-000000000101) от Бильбо,
а сам он родом из [Шира](codex_page:c0000000-0000-4000-8000-000000000101).
```

Подпись любая — та, которой удобно в этом предложении. Связь держит идентификатор, поэтому
переименование страницы или объекта ссылку не ломает. В приложении она открывает эдитор
сущности; в Obsidian и любом другом редакторе остаётся обычным текстом.

Идентификаторы берутся тулами: `find_codex_pages` для страниц, `list_world_objects` для
объектов. Придумывать их нельзя — повиснут, и `diagnose` покажет их как находку.

**Частью модели эти ссылки не являются.** Связь «объект → страница» живёт полем `codexPage` в
файле объекта, и ссылка в тексте её не заменяет и не дублирует.

## Связать объект со страницей

```
find_codex_pages {query: "Фродо"}          → путь и id страницы
update_world_object {objectId, codexPageId}
```

**Связь хранится только на стороне объекта**, встречного поля у страницы нет и заводить его
нельзя. Причина в том, что одной странице может быть посвящено несколько объектов: страница
«Назгулы» описывает и группу, и каждого всадника. Обратное — «про этот объект есть несколько
страниц» — выражается ссылками в тексте.

У события есть такое же поле `codexEntry`, правится через `update_event`.

## Теги

Теги сквозные: один и тот же тег стоит и на страницах кодекса, и на объектах мира. Файла у
тега нет — он живёт, пока стоит хотя бы на одной сущности, и снятый с последней исчезает сам.

Ставишь тег — сперва `list_tags`, чтобы не завести «локации» рядом с «Локации». Прибрать
разъехавшиеся — `merge_tags`, см. `references/maintenance.md`.

Частью модели теги не являются: связь между сущностями выражается свойствами и рёбрами, а не
совпадением тега.

## book.md

Метаданные книги — заголовок, автор, жанр, язык, `renderLength` — во frontmatter; описание
книги телом файла. Правится файловыми инструментами, как и кодекс.

Описание — то, по чему потом судят «подходит ли такая сцена этой книге». Если оно пустое, а
автор просит что-то сочинить, лучше спросить, чем угадывать.
