# Рукопись: проза над лентой

Ситуация: автор просит завести рукопись, показать, что уже написано, записать прозу сцены или
разобрать его замечания к тексту.

Рукопись — проза над одной лентой. Состав и порядок сцен она не хранит: берёт их у ленты, а сама
держит каталог версий прозы по сценам. Над одной лентой рукописей может быть сколько угодно, и у
каждой свой текст. **Правка ленты рукопись не меняет:** убранное с ленты событие пропадает из
состава, но проза его остаётся в каталоге и вернётся вместе с ним.

**Ключ прозы — событие плюс действующая перспектива ленты.** Сменили перспективу — видны тексты для
новой, прежние ждут в каталоге. Одно событие дважды на ленте с одной перспективой — один текст на
двоих. Тулы ищут сцену по первому месту события на ленте рукописи; события на ленте нет — отказ.

| Задача | Порядок |
|---|---|
| Посмотреть, какие есть | `list_manuscripts` |
| Завести | `create_manuscript` над лентой; сменить её потом нельзя |
| Что написано и что ждёт письма | `get_manuscript`: по сцене — текущая версия, длина против бюджета, пометки, сколько замечаний автора |
| Прочитать прозу сцены | `get_prose`, замечания автора — в тексте; старую версию — параметром `version` |
| Заметки к сцене | `get_scene_notes` — прочитать, без прозы; `set_scene_notes` — записать |
| Записать прозу сцены | `get_event_brief` по ленте рукописи, при надобности заметки к сцене — `set_scene_notes`, затем `write_prose` |
| Разобрать замечания автора | `get_prose`, правка, `write_prose` с `WriterByComments` — это работа правщика, порядок — `references/render.md` |
| Сверить прозу сцены с данными | `critique_prose` — критик; зовёт его писатель, порядок — `references/render.md` |
| Отчёт о работе писателя или правщика | `get_writer_report` с `agentId` агента: модель, усилие, токены, время, длина против бюджета |
| Переименовать, удалить | `update_manuscript`, `delete_manuscript` |

**Тулы версии только заводят.** `write_prose` пишет новую версию и прежних не меняет. Автор в
приложении правит текущую версию на месте, чья бы она ни была: версия писателя, которую он поправил,
помечена `editedByAuthor` — правки автора в ней сохраняй. Сделать старую версию текущей или
удалить неудачную тоже может только он.

**Пометки считаются, а не ставятся.** Версия помнит, из чего написана: сцену, соседей в порядке
чтения, лицо и разметку ленты. `get_manuscript` сверяет это с нынешним:

| Пометка | Что значит |
|---|---|
| `sceneChanged` | после версии правили резюме, дельту, участников, место действия или справку |
| `previousSeam`, `nextSeam` | сменился сосед в порядке чтения, либо автор пометил стык руками |
| `contextChanged` | у ленты другое лицо или другая разметка подачи |
| `invalidated` | автор объявил текст негодным |

Пометка — повод переписать сцену, а не ошибка. Новая версия снимает ручные пометки автора, а
вычисленные исчезают, когда версия написана по нынешнему состоянию.

**Бриф — по ленте рукописи.** Перспектива, лицо, разметка и бюджет — свойства ленты, и та же нода на
другой ленте даст другой бриф: для прозы рукописи брифом служит `get_event_brief` с её `tapeId`.

**Замечания автора стоят в тексте версии.** Автор ставит их в приложении к отрывкам текущей версии;
`get_prose` отдаёт текст с ними: отрывок — между `⟦N⟧` и `⟦/N⟧`, само замечание — абзацем
`⟦замечание N: …⟧` за абзацем, где отрывок кончается, номера по порядку в тексте. **Разметка только
для чтения:** `write_prose` и `critique_prose` текст с ней не примут. Новая версия начинается без
замечаний — прежние остаются при своей, и что учтено, говорит отчёт, а не отметка.

## Чего делать не нужно

- **Не читай файлы `manuscripts/`** — они закрыты правами и на чтение. Файл версии не скажет,
  текущая ли она, к какому месту ленты относится и что с тех пор изменилось в сцене; это знают тулы.
- **Не удаляй рукопись ради «начать заново».** Новая версия поверх старой — обычный ход: старые
  остаются историей, а удаление уносит и замечания автора.
